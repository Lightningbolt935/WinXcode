## 1. Classification Levels & Diagnostic Tiers

The preview engine classifies each target preview into one of four mutually exclusive levels:

- **CLEAN**: Lex OK, Parse OK, Render OK, 0 diagnostics, and $>3$ view nodes. View renders completely with full fidelity.
- **DEGRADED**: Lex OK, Parse OK, Render OK, $>3$ view nodes, but emits non-fatal diagnostic notes (e.g., `@degraded:*`, `@behavior:*`, `@ignored:*`, or runtime shims).
- **EMPTY**: Renders $\le 3$ view nodes. Counted as a failed render because student apps rendering empty views or trivial placeholders fail preview requirements.
- **FAILED**: Lex/Parse fatal errors, uncaught runtime render exception, or explicit unsupported root constructs (e.g., `Unsupported: "Chart"`).

### Diagnostic Tiers
- **`@behavior:*` (Behavior Skipped)**: Modifiers that change runtime behavior or data flow without affecting the visual preview layout (e.g., `.task`, `.onAppear`, `.onChange`, `.environment`, `.environmentObject`).
- **`@degraded:*` (Degraded Visual / Missing Feature)**: Modifiers or components with visual or interactive impact that the preview cannot fully render (e.g., `.swipeActions`, `.toolbar`, `TimelineView` static frame).
- **`@ignored:*` (Ignored / No-Op)**: Modifiers with truly no effect on preview layout or interaction (e.g., accessibility labels, `.flipsForRightToLeftLayoutDirection`).

## 5. Architectural Findings & Context Notes

### Why Corpus 08 (Game) Is Classified as DEGRADED
In Phase 3a, `DragGesture` event dispatch was wired up into the preview runtime, resolving `@behavior:gesture`. Because `08 Game` evaluated without runtime crashes, its diagnostic count dropped to 0, which would naively score it as CLEAN.
However, `08 Game` relies on `TimelineView(.animation)` to drive a 60fps continuous game loop. WinXcode's preview engine evaluates a single static snapshot at `Date.now()`. Calling it CLEAN was misleading because the user sees a still frame and the game loop does not advance.
Under the honest Phase 3b rule, any app utilizing `TimelineView` or time-driven animation where only a static frame is rendered emits `@degraded:animation not run` and is classified as **DEGRADED**.

### Support for @Observable Models
The XWinCode preview engine natively supports `@Observable` classes without requiring a Swift compiler macro expansion pass. Reference semantics are maintained via unique object IDs and field maps in `runtime.ts`. Shared observable dependencies declared via `@Environment(Type.self)` and `@Bindable` resolve dynamically through runtime type registration.
